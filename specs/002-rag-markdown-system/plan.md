## Summary

Implement a Retrieval-Augmented Generation (RAG) system that allows users to query Markdown (.md) files using natural language. The system will use Qdrant as a vector database to store embeddings generated by Google's Gemini model, enabling semantic search and context-aware response generation. The implementation will follow the architectural constraints of the constitution, specifically avoiding OpenAI services and using exclusively Gemini for embeddings and responses.

## Technical Context

**Language/Version**: Python 3.11
**Primary Dependencies**: FastAPI, Qdrant, Google's Gemini (gemini-2.5-flash), Pydantic, python-qdrant-client
**Storage**: Qdrant vector database for embeddings, local file system for Markdown files
**Testing**: pytest for unit and integration tests
**Target Platform**: Linux server (Railway deployment)
**Project Type**: Web application (API backend)
**Performance Goals**: Responses within 5 seconds, handle 10 concurrent queries
**Constraints**: <200ms p95 for retrieval, <10MB file size limit, no OpenAI services allowed
**Scale/Scope**: Support 1000+ documents, 10 concurrent users

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

1. **Gemini-Centric AI Integration**: Implementation must use Google's Gemini models exclusively (gemini-2.5-flash) - NO OpenAI services allowed anywhere in the system.
2. **Test-First (NON-NEGOTIABLE)**: All API endpoints must have comprehensive unit and integration tests before implementation.
3. **RAG System Excellence**: Document chunking must be sane and retrieval-safe with proper context handling; Qdrant operations must be optimized for fast similarity search.
4. **Security and Observability**: API keys must be handled via environment variables; structured logging must be implemented for all operations.
5. **Semantic Search First**: All search functionality must be powered by semantic understanding rather than keyword matching.
